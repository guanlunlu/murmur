# 音訊來源與轉錄

[返回 README](../../README.md) · [HTTP API](../reference/http-api.md)

Murmur 可以處理播放中的媒體檔案，也可以收錄即時音訊。瀏覽器會以語音活動偵測（VAD）切分音訊，再送到同一個本機轉錄服務。頁面初始沒有示範音檔，需自行上傳媒體、貼入 YouTube 連結，或選擇收音裝置。

## 載入檔案與快速轉錄

上傳瀏覽器支援的音訊或影片後，可以播放並同步轉錄。按「⚡ 快速轉錄」則不播放聲音，直接解碼整個檔案並送往本機 ASR；頁面會顯示進度，也可以按同一按鈕停止。

後端處理方式取決於 ASR 能力：

- vLLM 串流 CUDA 使用有狀態的 session，每段最多 25 秒。
- MLX 與 Transformers 等非串流後端使用 `/api/transcribe`，通常每段 10 秒；不足 1 秒的尾段會併入前一段。

一般播放或現場收音時，瀏覽器傳送單聲道 16 kHz Float32 PCM，並在自然停頓處切段，通常約 1–16 秒。模型產生的文字會接到逐字稿；若摘要已開啟，片段也會送入會議狀態流程。

## 收音來源

頁面上的「收音來源」可選擇：

| 模式 | 使用方式 | 時間來源 |
| --- | --- | --- |
| 播放檔案 | 使用頁面中的音訊／影片播放器 | 媒體播放位置 |
| 麥克風 | 從「輸入裝置」選擇麥克風 | 錄製開始後的經過時間 |
| 系統音／會議音 | 在瀏覽器分享對話框勾選分頁或系統音訊 | 錄製開始後的經過時間 |
| 麥克風＋系統音 | 混合雙方音訊成單聲道 | 錄製開始後的經過時間 |

即時來源沒有可拖曳的播放時間軸；頁面會顯示 `LIVE`，並停用時間軸與靜音控制。錄製中切換輸入裝置，逐字稿時間仍會接續。麥克風音訊不會播放回喇叭，以免造成回授。

在 macOS 上也可使用 BlackHole 等虛擬輸入裝置：先將會議軟體輸出導向它，再在 Murmur 的「麥克風」模式中選取該裝置。

## 音訊處理細節

瀏覽器會關閉自動增益（AGC）、降噪與回音消除，避免音量閘門失真，或把混合收音中的遠端語音消掉。系統音音量變化較大，所以 VAD 在各模式的基本門檻上另會追蹤較慢變化的背景噪音；裝置選擇器下方的音量表顯示目前偵測到的音量。

即時字幕的更新方式也取決於後端。vLLM 可以保留串流狀態並逐秒解碼；非串流後端會在語句尚未結束時重轉錄目前累積的片段，長句的暫時字幕可能延遲。最終逐字稿仍以語句結束時的結果為準。

## YouTube 連結

將 YouTube 連結貼到頂部欄位並按「載入」。服務使用 `yt-dlp` 下載純音訊到 `dist/uploads/`，依影片 ID 快取，再當成同源媒體交給頁面。只接受 `youtube.com` 與 `youtu.be` 連結。下載需要網路，也須遵守 YouTube 的服務條款；此功能供本機個人測試轉錄流程使用。

對應[部署文件](../deployment/mac.md)與 [NVIDIA 部署文件](../deployment/nvidia.md)的安裝指令已包含 `yt-dlp`。如果現有環境缺少套件，請在執行後端的同一個 Python 環境安裝。
